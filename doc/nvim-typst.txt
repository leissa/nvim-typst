==============================================================================
1. INTRODUCTION                                      *nvim-typst-introduction*

nvim-typst is a Typst plugin for Neovim, the sibling of nvim-tex. It has the
same interface -- the same mappings, commands, option names and events, with
`Tex` replaced by `Typst` -- and the same two restrictions:

  - Neovim only. There is no Vim compatibility layer and no Vimscript.
  - Structure comes from tree-sitter, language intelligence from the LSP.
    The plugin has no Typst parser and no syntax-group heuristics of its own.

Motions, text objects, the `ds`/`cs`/`ts` edits, the table of contents,
indentation, folding and conceal read the `typst` parse tree; completion,
diagnostics, references and rename come from tinymist. What the plugin
itself provides is the part neither covers: finding the main file of a
multi-file document, driving `typst watch` and `typst compile`, the quickfix
list, opening the PDF or tinymist's live preview, and citing from DBLP.

==============================================================================
2. REQUIREMENTS                                      *nvim-typst-requirements*

Required:
  - Neovim 0.10 or newer (0.11+ recommended)
  - `typst`: https://github.com/typst/typst
  - The `typst` tree-sitter parser: `:TSInstall typst`

Optional but recommended:
  - `tinymist` for completion, diagnostics, references, renaming and
    formatting, and for the live preview with forward and inverse search
    (|nvim-typst-preview|): https://github.com/Myriad-Dreamin/tinymist
  - A PDF viewer that reloads a changed file: zathura, sioyek, okular, Skim
  - `curl` for |:TypstCite|

Run `:checkhealth nvim-typst` to see what is available.

==============================================================================
3. INSTALLATION                                      *nvim-typst-installation*

Calling `setup` is optional. The defaults apply as soon as the plugin is
loaded; call |nvim-typst-setup()| only to change them.

lazy.nvim: >lua

    {
      'leissa/nvim-typst',
      ft = { 'typst' },
      opts = {},
    }
<
`opts = {}` only exists to make lazy.nvim call `setup`.

`vim.pack` (Neovim 0.12+): >lua

    vim.pack.add({ 'https://github.com/leissa/nvim-typst' })
<
Native |packages|: >sh

    git clone https://github.com/leissa/nvim-typst \
      ~/.local/share/nvim/site/pack/plugins/start/nvim-typst
<
Run `:helptags ALL` afterwards if your plugin manager does not generate help
tags for you.

4. CONFIGURATION                                    *nvim-typst-configuration*

                                                          *nvim-typst-setup()*
>lua
    require('nvim-typst').setup({
      compiler = {
        typst = {
          continuous = true,
          out_dir = 'build',
        },
      },
      view = { method = 'tinymist' },
      fold = { enabled = true },
      mappings = { prefix = '<localleader>' },

<

`enabled`                     Set to false to disable the plugin entirely.
`filetypes`                   Filetypes to attach to.
`main_file`                   Force the main file. A string, or a
                            function(bufnr) returning a path. See
                            |nvim-typst-main-file|.
`root_markers`                Files marking the project root, Typst's
                            `--root`. Default `{ 'typst.toml', '.git' }`.
`cache_root`                  Where scratch data is kept.

`compiler.enabled`            Enable the compiler interface.
`compiler.method`             `'typst'`, the only backend so far.
`compiler.silent`             Suppress start/stop/success messages.
`compiler.build_on_save`      Run a single shot compilation on `:write`.
`compiler.typst.*`            See |nvim-typst-compiler|.

`view.*`                      See |nvim-typst-viewer|.
`qf.*`                        See |nvim-typst-quickfix|.
`lsp.*`                       See |nvim-typst-lsp|.
`treesitter.*`                See |nvim-typst-treesitter|.
`indent.*`                    See |nvim-typst-indent|.
`fold.*`                      See |nvim-typst-fold|.

5. MAPPINGS                                              *nvim-typst-mappings*

All mappings are buffer-local and are created when the plugin attaches to a
Typst buffer. The keys are nvim-tex's; those whose nvim-tex action has no
Typst counterpart are left unmapped. >lua

    require('nvim-typst').setup({
      mappings = {
        enabled = true,          -- all mappings
        prefix = '<localleader>',
        motions = true,          -- ]] [[ ]n ... (n, x, o)
        text_objects = true,     -- a$ i$ ac ic ... (x, o)
        surround = true,         -- ds$ cs$ ts$ <F6> <F7> tse ...
        insert_close = false,    -- ]] in insert mode
        doc_package = true,      -- K
      },
    })
<
                                                  *nvim-typst-leader-mappings*
  LHS                 ACTION                                       MODE ~
  <localleader>i      project information                            `n`
  <localleader>I      project information, full                      `n`
  <localleader>t      open the table of contents                     `n`
  <localleader>T      toggle the table of contents                   `n`
  <localleader>v      view the PDF, or start the tinymist preview    `n`
                      and scroll it to the cursor
  <localleader>l      start or stop compilation                      `n`
  <localleader>L      compile the lines a motion covers, or the     `n x`
                      selection, as a document of its own
  <localleader>S      compile once                                   `n`
  <localleader>k      stop the compilation                           `n`
  <localleader>K      stop all compilations                          `n`
  <localleader>e      open the quickfix list                         `n`
  <localleader>E      cycle the quickfix severity level              `n`
  <localleader>o      show the raw compiler output                   `n`
  <localleader>g      compilation status                             `n`
  <localleader>G      compilation status of all projects             `n`
  <localleader>c      clean generated files (typst leaves none)      `n`
  <localleader>C      clean all output, the PDF included             `n`
  <localleader>a      context menu: reference, citation, include     `n`
  <localleader>b      search DBLP and cite                           `n`
  <localleader>m      list the insert mode math mappings             `n`
  <localleader>p      preview the math or code under the cursor,    `n x`
                      or the selected lines, cropped
  <localleader>x      reload nvim-typst                              `n`
  <localleader>X      forget all project state                       `n`
  <localleader>s      toggle the main file                           `n`

nvim-tex's `<localleader>r` (inverse search) and `q` (the log) have no Typst
counterpart.

                                                              *nvim-typst-K*
`K` opens the documentation of the package imported under the cursor: the
Typst Universe page of an `@preview/...` package (with |vim.ui.open()|), the
README of any other, downloaded one. Everywhere else it shows the LSP hover,
as Neovim's own `K` would. `mappings.doc_package = false` leaves `K` alone.

The editing mappings, `ds$`, `csc`, `tsf`, `<F7>` and friends, are described
in |nvim-typst-surround|.

------------------------------------------------------------------------------
Motions                                                  *nvim-typst-motions*

Motions work in normal, visual and operator-pending mode and take a count.
They read the `typst` parse tree, so a `=` in raw text or a `$` in a string
is never mistaken for a heading or math. Disable them with
`mappings.motions = false`.

  `]]`  `[[`     start of the next / previous heading       *nvim-typst-]]*
  `][`  `[]`     end of the next / previous section         *nvim-typst-][*
                 (the last non-blank character before the next heading of
                 the same or a higher level)
  `]n`  `[n`     start of the next / previous math          *nvim-typst-]n*
  `]N`  `[N`     end of the next / previous math            *nvim-typst-]N*
  `]m`  `[m`     the `#` of the next / previous function    *nvim-typst-]m*
                 call in markup, such as `#emph[...]` or `#figure(...)[...]`;
                 `#let`, `#set`, `#show` and plain expressions are skipped
  `]M`  `[M`     end of the next / previous such call       *nvim-typst-]M*
  `]/`  `[/`     start of the next / previous comment       *nvim-typst-]/*
  `]*`  `[*`     end of the next / previous comment         *nvim-typst-]star*
  `%`            on a `$`, the other `$` of the same math;  *nvim-typst-%*
                 on the `*` or `_` of strong or emphasis, the other one;
                 anywhere else the built-in |%|. As an operator target it is
                 inclusive, like the built-in: `d%` on a `$` deletes the
                 whole math.

Headings are nested: `]]` stops at every heading, whatever its level. Typst
has no environments or frames, so nvim-tex's `]r` / `[r` have no
counterpart; `]m` / `[m`, which jump between `\begin`s there, jump between
function calls here.

------------------------------------------------------------------------------
Text objects                                        *nvim-typst-text-objects*

Text objects work in visual and operator-pending mode. Disable them with
`mappings.text_objects = false`.

  `a$`  `i$`     math                                      *nvim-typst-a$*
                 `i$` leaves the `$` and the spaces inside them behind, so
                 `di$` on `$ x + y $` leaves `$  $`.
  `aP`  `iP`     section: the heading and everything up to  *nvim-typst-aP*
                 the next heading of the same or a higher level,
                 subsections included, linewise. `iP` leaves the heading
                 behind.
  `ac`  `ic`     function call                             *nvim-typst-ac*
                 `ac` is the whole call, trailing content blocks and the
                 `#` in front of it included: `dac` on `#emph[x]` leaves
                 nothing behind. `ic` is the inside of the argument list or
                 content block under the cursor, or of the last one when the
                 cursor is on the name: on `#figure(...)[body]` that is
                 `body`. Calls in math, such as `frac(a, b)`, count too.
  `ad`  `id`     delimiters: `(...)`, `[...]` and `{...}`   *nvim-typst-ad*
                 in code, groups in math whatever their bracket, and the
                 parentheses of a call in math. In markup, where brackets
                 are plain text, the nearest `(...)`, `[...]` or `{...}` is
                 searched for instead.
  `am`  `im`     list item (`-`), enumeration item (`+`,    *nvim-typst-am*
                 `1.`) or term (`/ Term: ...`). `am` is linewise when the
                 item has its lines to itself; `im` leaves the marker
                 behind. Nested items belong to the item they are in.

When the delimiters of `ic`, `id` and `i$` sit on lines of their own, the
inner object selects the lines in between, linewise. nvim-tex's `ae` / `ie`
(environments) have no Typst counterpart.

6. COMMANDS                                              *nvim-typst-commands*

Every command acts on the project of the current buffer.

:TypstCompile                                                  *:TypstCompile*
    Start compiling; stop if a compilation is running. In continuous mode
    this runs `typst watch`, which rebuilds on every change until stopped.

:TypstCompileSS                                              *:TypstCompileSS*
    Compile once with `typst compile`, whatever `continuous` says.

:[range]TypstCompileSelected                           *:TypstCompileSelected*
    Compile the lines in [range] (default: the whole buffer) as a document
    of its own, with the preamble of the main file in front, and show it:
    below the lines with snacks.nvim, or else in the PDF viewer. See
    |nvim-typst-compile-selected|.

:[range]TypstPreviewFragment                           *:TypstPreviewFragment*
    Compile the math or code under the cursor, or the lines in [range], on
    a page cropped to it, and show it below. See |nvim-typst-fragment|.

:TypstPreviewClose                                        *:TypstPreviewClose*
    Remove the fragment shown in the buffer.

:TypstCompileOutput                                      *:TypstCompileOutput*
    Show the raw output of the compiler.

:TypstStop                                                        *:TypstStop*
:TypstStopAll                                                  *:TypstStopAll*
    Stop the compilation of this project, or of all projects.

:TypstClean[!]                                                   *:TypstClean*
    Remove generated files. Typst writes nothing but the PDF, so without the
    bang there is nothing to do; with it the PDF is removed.

:TypstView                                                        *:TypstView*
    Open the PDF, unless the viewer started earlier is still running. With
    the tinymist preview: start it, or scroll it to the cursor once it runs.

:TypstForwardSearch                                      *:TypstForwardSearch*
    Scroll the tinymist preview to the cursor, starting it first if it is
    not running. Needs `view.method = 'tinymist'`.

:TypstViewClose                                              *:TypstViewClose*
    Close the viewer: stop the tinymist preview, or end the PDF viewer
    nvim-typst started.

:TypstErrors                                                    *:TypstErrors*
    Fill and open the quickfix list from the last run.

:TypstQfLevel [level]                                          *:TypstQfLevel*
    Set the lowest severity shown in the quickfix list, `error` or
    `warning`, or cycle it without an argument.

:TypstStatus                                                    *:TypstStatus*
:TypstStatusAll                                              *:TypstStatusAll*
    Report the compilation status of this project, or of all projects.

:TypstInfo[!]                                                     *:TypstInfo*
    Show the project: main file, root, output, compiler, LSP, parser and
    viewer. With the bang also the included files and the configuration.

:TypstToc                                                          *:TypstToc*
:TypstTocToggle                                              *:TypstTocToggle*
    Open or toggle the table of contents. See |nvim-typst-toc|.

:TypstCite [query]                                                *:TypstCite*
    Search DBLP for a paper, add its BibTeX entry to the bibliography and
    cite it at the cursor. Without [query], asks for one. See
    |nvim-typst-cite|.

:TypstContextMenu                                          *:TypstContextMenu*
    Act on what is under the cursor. See |nvim-typst-context-menu|.

:TypstDocPackage                                          *:TypstDocPackage*
    Open the documentation of the imported package under the cursor. See
    |nvim-typst-K|.

:[range]TypstEnvSurround [name]                          *:TypstEnvSurround*
    Wrap [range] (the current line by default) in the content block of the
    call [name], asking for it when it is not given. See |nvim-typst-<F6>|.

:TypstImaps                                                      *:TypstImaps*
    List the insert mode math mappings. See |nvim-typst-imaps|.

:[range]TypstCountWords[!]                                  *:TypstCountWords*
    Count the words of the whole document, following `#include`s from the
    main file, or only those of [range] in the current buffer. With [!],
    show a per-file report instead. See |nvim-typst-count|.

:[range]TypstCountLetters[!]                              *:TypstCountLetters*
    The same for letters.

:TypstToggleMain                                            *:TypstToggleMain*
    Toggle the main file between the detected one and the current buffer.

:TypstReload                                                    *:TypstReload*
    Reload the plugin's Lua modules, keeping the configuration.

:TypstReloadState                                          *:TypstReloadState*
    Forget all project state; the main files are detected anew.

7. THE MAIN FILE                                        *nvim-typst-main-file*

Compilation always runs on the project's main file, never on the buffer you
happen to be in. It is the first of:

  1. `b:typst_main`, which |:TypstToggleMain| sets.
  2. The `main_file` option.
  3. A directive in the first or last five lines of the buffer: >typst
         // !TYPST main = thesis.typ
<    It is `main` rather than LaTeX's `root` because "root" means something
     else in Typst. A missing `.typ` extension is added.
  4. An open project whose main file `#include`s or `#import`s the buffer.
  5. A file in this or up to five parent directories that includes or
     imports the buffer, followed up the chain: a chapter included by a part
     included by the thesis resolves to the thesis. The search does not leave
     the directory holding a root marker.
  6. The buffer itself. Typst has no `\begin{document}`: every file compiles
     on its own.

The project root, Typst's `--root`, is the nearest directory at or above the
main file holding one of `root_markers`, or the main file's directory. Typst
only reads files inside the root, and resolves absolute paths such as
`/figures/a.svg` against it. The compiler runs there and tinymist is rooted
there too.

8. COMPILER                                              *nvim-typst-compiler*

`compiler.typst` holds the options of the `typst` backend:

`executable`    `'typst'`, or a list such as `{ 'nix', 'run', 'nixpkgs#typst',
              '--' }`.
`continuous`    `true` (the default) runs `typst watch`; `false` makes every
              |:TypstCompile| a single `typst compile`.
`options`       Extra flags, e.g. `{ '--font-path', 'fonts' }`. `--root` and
              `--diagnostic-format short` are always passed.
`out_dir`       Where the PDF goes, relative to the main file's directory.
              Empty (the default) puts it next to the main file.
              `$NVIM_TYPST_OUTPUT_DIRECTORY` overrides it.
`hooks`         Functions called with every line of compiler output.

In continuous mode every watch cycle is reported on its own: its diagnostics
replace the quickfix list, and a success or failure message and event follow.
The compilations are stopped when Neovim exits.

                                               *nvim-typst-compile-selected*
Compiling a selection ~

`<localleader>L` and |:TypstCompileSelected| compile a few lines on their own,
for a quick look at a figure, a table or a formula without the rest of the
document. In normal mode `<localleader>L` is an operator
(`<localleader>Lip`), in visual mode it takes the selected lines.

The lines are put after the preamble of the main file: the lines before its
first content, as long as they hold nothing but `#set`, `#show`, `#import`
and `#let` statements and comments. A `#show: template.with(...)` is part of
it, so the fragment is typeset with the document's template. When the lines
come from the main file itself, no preamble is added.

The fragment is written to a hidden file, `.<name>.selected.typ`, next to the
buffer's file, so that relative paths in it resolve as they do in the
document; relative `#import`s of the preamble are rewritten against the
project root. The file is removed once the compilation is over. The PDF,
`selected.pdf`, goes to the project's directory under `cache_root` and is
opened with the PDF viewer, `view.general`, even when `view.method` is
`tinymist`: the preview needs a source file, which the fragment no longer
has. Errors are shown in the quickfix list at the lines of the buffer they
come from (or of the main file, for the preamble).

With snacks.nvim (|nvim-typst-snacks|) the fragment is instead rendered as an
image, as tall as its content, and shown below its last line.

The selection is compiled once, as a single shot, whatever
`compiler.typst.continuous` says. Needs the `typst` tree-sitter parser to find
the preamble.

9. VIEWER                                                  *nvim-typst-viewer*

`<localleader>v` (|:TypstView|) opens the document. What that means depends
on `view.method`:

  `general`    Open the PDF with `view.general.executable` (the desktop's
               default application by default). Typst writes no SyncTeX
               data, so a PDF viewer gets no forward or inverse search.
               Viewers that watch the file (zathura, sioyek, okular, Skim)
               reload it after every compilation on their own, and one that
               is still running is not started a second time.
  `tinymist`   Open tinymist's live preview in the browser, with forward
               and inverse search. See |nvim-typst-preview|.

`general` is the default because it is what the rest of the plugin builds:
a PDF, which is what one sends to others. The preview is the better editing
companion. >lua

    view = {
      enabled = true,
      method = 'general',          -- or 'tinymist'
      general = {
        executable = 'xdg-open',   -- `open` on macOS
        args = { '@pdf' },
      },
      tinymist = {
        executable = 'xdg-open',   -- `open` on macOS; false: report the URL
        args = { '@url' },
        options = {},              -- extra flags for `tinymist preview`
        follow_cursor = false,
        follow_delay = 100,
      },
    }
<
`xdg-open`, the default, hands the PDF to another process and exits at once,
so with it every |:TypstView| opens the PDF anew. Set
`view.general.executable = 'zathura'` or similar to keep one viewer.

                                                          *nvim-typst-preview*
The tinymist preview ~

With `view.method = 'tinymist'` the viewer is tinymist's live preview, the
Typst counterpart of a SyncTeX viewer. It runs inside the tinymist language
server (|nvim-typst-lsp|), which renders the main file into a page served on
a free local port and opens it with `view.tinymist.executable`. The preview
renders the buffers as they are, unsaved changes included, so it needs no
compilation: it updates as you type.

Forward search: the first `<localleader>v` starts the preview. Once it runs,
`<localleader>v` and |:TypstForwardSearch| scroll it to the cursor, in the
main file or in any file it includes. With `view.tinymist.follow_cursor` the
preview follows the cursor on its own.

Inverse search: a click in the preview jumps to the clicked spot in Neovim.
tinymist pushes the jump as a `window/showDocument` request, which Neovim's
LSP client answers itself, so there is nothing to set up and no mapping for
it.

|:TypstViewClose| stops the preview. Closing the browser tab leaves it
running; `<localleader>v` then scrolls a preview nobody sees, so either
reopen the URL (|:TypstInfo| shows it) or close and restart the preview.

The preview needs the tinymist client that nvim-typst starts, or one you
configured yourself under the name `lsp.name`.

`view.tinymist.executable`    Opens the preview's URL; `@url` in `args` is
                            substituted. `false` opens nothing and only
                            reports the URL, e.g. to open it in a browser
                            of your choice.
`view.tinymist.options`       Extra flags for `tinymist preview`, e.g.
                            `{ '--invert-colors=auto' }` for a dark preview
                            or `{ '--preview-mode=slide' }` for slides.
                            `--task-id`, `--data-plane-host`, `--no-open`
                            and `--root` are passed by nvim-typst itself.
`view.tinymist.follow_cursor` Scroll the preview along whenever the cursor
                            moves, once it has rested for
                            `view.tinymist.follow_delay` milliseconds.

                                                         *nvim-typst-fragment*
Previewing a fragment ~

`<localleader>p` (|:TypstPreviewFragment|), nvim-tex's TikZ preview for
Typst, compiles what is under the cursor on its own, on a page cropped to it:
the outermost math around the cursor, or else the outermost embedded code
that is not a definition, such as `#figure(...)`, `#table(...)` or
`#cetz.canvas(...)`. In visual mode, and with a [range], it takes the lines
instead.

The fragment is set in the document it comes from, as with
|nvim-typst-compile-selected|: after the preamble of the main file, and after
the top-level `#let`, `#set`, `#show` and `#import` statements of the buffer
before it. A `#show: template` is left out, since a template typesets a
title block and the like, which would end up in the preview; its fonts and
settings go with it. Then `#set page(width: auto, height: auto, ...)` crops
the page, without header, footer or page number. Errors go to the quickfix
list, at the lines of the buffer they come from.

`preview.border`   Space around the cropped fragment. Default `'2pt'`.

                                                           *nvim-typst-snacks*
Fragments in the buffer ~

With snacks.nvim (https://github.com/folke/snacks.nvim) and its image
support enabled, in a terminal that can show images (kitty, ghostty, WezTerm),
|:TypstPreviewFragment| and |:TypstCompileSelected| show the fragment right
below its last line instead of in the viewer. typst renders it as a PNG
itself, so nothing needs converting. Terminals with unicode placeholders get
the image in virtual lines that move with the text, others a floating window
anchored to the line. The image stays until the next fragment replaces it,
or |:TypstPreviewClose|. Without snacks the PDF opens in the viewer, which a
viewer that watches the file reloads on the next run. >lua

    view = {
      snacks = {
        enabled = true,   -- false: always the viewer
        scale = 2,        -- magnification over the printed size
      },
    }
<
`snacks.image.doc.max_width` and `max_height` bound the image.
`:checkhealth nvim-typst` says whether snacks can show fragments.

10. QUICKFIX                                             *nvim-typst-quickfix*

typst's diagnostics fill the quickfix list after every run, errors first.
Paths are resolved against the project root; a diagnostic inside a package
(`@preview/cetz:0.3.1/src/draw.typ`) points into the package directory, and
one without a location goes to the main file.

`qf.enabled`          Collect diagnostics at all.

12. TREE-SITTER                                        *nvim-typst-treesitter*

nvim-typst reads the parse tree of https://github.com/uben0/tree-sitter-typst,
the grammar nvim-treesitter installs.

`treesitter.enabled`              Use the parser.
`treesitter.warn_missing_parser`  Warn once when it is missing.
`treesitter.highlight`            Start tree-sitter highlighting.

Neovim ships no highlight query for Typst; nvim-treesitter does. Without one,
`syntax/typst.vim` stays in charge of highlighting.

                                                           *nvim-typst-indent*
Indentation ~

nvim-typst sets 'indentexpr' for Typst buffers, so `=`, `o`, `O` and typing
work structurally:

  - The contents of a multi-line `( ... )`, `[ ... ]`, `{ ... }` and
    `$ ... $` are indented one level.
  - A line starting with a closing delimiter lines up with the line that
    opened it.
  - In a list, a nested item and the lines continuing an item sit one level
    into the item. `o` below an item stays at its level, ready for the next
    one; a line after a blank line leaves the list.
  - Raw blocks, block comments and multi-line strings keep whatever
    indentation their contents have.

The parse tree decides what counts as a delimiter, so a bracket in markup
text, a string or a comment is ignored. In a list the indentation is the
structure -- a line indented under `- item` continues the item -- so `=`
follows what the tree already says and never moves a line into or out of an
item. 'indentkeys' reindent the line when it starts with a typed `)`, `]`,
`}` or `$`.

`indent.enabled` (default `true`) switches it. Without the `typst` parser, or
with `enabled = false`, Neovim's own `indent/typst.vim` stays in charge.

                                                             *nvim-typst-fold*
Folding ~

Folding is off by default. With it on, 'foldmethod' is `expr` and
'foldexpr' is |vim.treesitter.foldexpr()|, which computes the folds from the
parse tree and keeps them up to date as you type. Neovim ships no fold query
for Typst, so nvim-typst installs its own; it takes precedence over the one
from nvim-treesitter. >lua

    fold = {
      enabled = false,
      sections = true,           -- = Heading up to the next heading, nested
      code = true,               -- multi-line ( ... ), [ ... ], { ... }
      math = true,               -- multi-line $ ... $
      raw = true,                -- ```lang ... ```
      comments = true,           -- /* ... */ and runs of // comments
    }
<
A section fold runs up to the line before the next heading of the same or a
higher level, so the blank lines between two sections fold with the first.
The options are read whenever the folds are computed. Neovim only recomputes
them when the text changes, so after changing an option, `:edit` the buffer
to see the effect (`zx` is not enough).

Nothing else is set. 'foldlevel', 'foldtext' and friends are yours: for
example, `vim.opt.foldlevel = 99` starts with every fold open, and
`vim.opt.foldtext = ''` shows the first line of a fold highlighted.

13. EDITING                                              *nvim-typst-surround*

nvim-tex's `ds*`, `cs*` and `ts*` mappings, translated to Typst. They act on
the tree-sitter node under the cursor, so nesting and line breaks do not
matter. Typst has no environments, starred commands, `\\` line breaks or
`\left`/`\right`, so `dse`, `cse`, `tss`, `tsc` and `tsb` have no
counterpart and are not mapped; `lr(…)` stands in for `\left…\right`. Of the environment mappings, <F6> wraps
lines in a content block and `tse` toggles lists. `mappings.surround = false`
turns the whole group off.

  ds$  cs$  ts$        delete / change the layout of / toggle math
  dsc  csc             unwrap / rename the surrounding function call
  dsd  csd             delete / change delimiters
  tsd  tsD             cycle `lr(…)` around delimiters (forwards / back)
  <F8>                 wrap every bracket pair of the math in `lr(…)`
  tsf                  toggle `a/b` and `frac(a, b)` (also visual)
  <F6>                 wrap the line / selected lines in a call (n, x)
  <F7>                 wrap word / selection in a call (n, x, i)
  tse                  toggle the list between `-` and `+`
  ]]                   close the innermost bracket or math (insert mode,
                       only with `mappings.insert_close`)

Math ~
                                                              *nvim-typst-ds$*
ds$             Delete the `$` of the math around the cursor. The spaces
                that make displayed math (`$ x $`) go too, and a `$` alone on
                its line takes the line along.

                                                              *nvim-typst-cs$*
cs$             Change the layout of the math around the cursor. Asks for
                one of
                  `inline`   (`i`)  `$x$`
                  `display`  (`d`)  `$ x $`
                  `lines`    (`l`)  each `$` on a line of its own

                                                              *nvim-typst-ts$*
ts$             Toggle between inline and displayed math. Inline math
                becomes displayed math laid out as `edit.display_math`
                says; displayed math of either layout becomes inline, its
                lines joined.

Function calls ~
In Typst, `#emph[x]` is what `\emph{x}` is in LaTeX, so the "command"
mappings work on function calls. `*x*` and `_x_` count as the calls they
stand for, `#strong[x]` and `#emph[x]`.

                                                              *nvim-typst-dsc*
dsc             Unwrap the call around the cursor, keeping its content:
                `#emph[x]` and `#text(red)[x]` become `x`, `_x_` becomes
                `x`, `sqrt(x)` in math becomes `x`. A call without a content
                block keeps its arguments. In code, the content block stays
                a value: `strong[x]` becomes `[x]`.

                                                              *nvim-typst-csc*
csc             Rename the call around the cursor; `#text(red)[x]` keeps its
                arguments. On `*x*` or `_x_` the markup is replaced by a
                call of the new name, `#underline[x]`.

                                                              *nvim-typst-tsf*
tsf             Toggle the fraction around the cursor between `a/b` and
                `frac(a, b)`. Parentheses that only group an operand are
                dropped, `(a+1)/2` becomes `frac(a+1, 2)`, and added again in
                the other direction. In visual mode every fraction in the
                selection is toggled.

                                                             *nvim-typst-<F7>*
<F7>            Normal mode: wrap the word under the cursor in a call, asking
                for the name -- `#name[word]` in markup, `name(word)` in math
                and code. Visual mode: the same with the selection.
                Insert mode: turn the word before the cursor into a call,
                `#word[|]` or `word(|)`, with the cursor inside.

                                                             *nvim-typst-<F6>*
<F6>            nvim-tex's environment surround: put the line under the
                cursor, or the selected lines, into the content block of a
                call on lines of their own, asking for the name, and indent
                them one level ('shiftwidth', 'expandtab'). >
                    #block[
                      Some text.
                    ]
<               In math the call gets parentheses, `cases(` ... `)`. The
                name may carry arguments: `box(stroke: red)`. See also
                |:TypstEnvSurround|.

Lists ~
                                                              *nvim-typst-tse*
tse             nvim-tex toggles `itemize` and `enumerate`; this toggles the
                list around the cursor between bullets (`- x`) and numbers
                (`+ x`). The list is the run of items of one kind that the
                cursor's item belongs to, blank lines between them allowed;
                a nested list is left as it is, and numbered items like
                `2. x` become bullets.

Delimiters ~
                                                              *nvim-typst-dsd*
dsd             Delete the brackets around the cursor: `(…)`, `[…]` or
                `{…}`. The brackets of a call, `#f(x)` or `#emph[x]`, and
                of `#(…)` / `#[…]` are skipped, since removing them would
                break the syntax.

                                                              *nvim-typst-csd*
csd             Change those brackets. Asks for a key of `edit.delim_list`.

                                                *nvim-typst-tsd* *nvim-typst-tsD*
tsd             Typst's counterpart of cycling `\left…\right`: step the
tsD             brackets around the cursor through
                `edit.delim_toggle_mod_list`, bare first. With the default
                list, which has only `lr(…)`, both wrap the brackets in
                `lr(…)` or unwrap them again. `tsD` steps backwards; a
                [count] takes several steps. An `lr(…)` that is not in the
                list is replaced by the next entry. Math only.

                                                             *nvim-typst-<F8>*
<F8>            Wrap every bare bracket pair of the math around the cursor
                in the first entry of `edit.delim_toggle_mod_list`,
                `lr(…)`; outside math, of all the math in the buffer.
                Brackets with a modifier already, and those of calls like
                `f(x)`, are left alone.

                                                             *nvim-typst-i_]]*
]]              Insert mode, only with `mappings.insert_close = true`: close
                the innermost open bracket or math at the cursor. The text is
                scanned the way Typst reads it, so only brackets that belong
                to code or math count -- the parenthesis in "(see above" does
                not -- and strings, raw text, comments and escapes are
                skipped. Math opened as displayed math, `$ x`, is closed with
                ` $`. It is off by default because `]]` is ordinary Typst,
                `#strong[#emph[x]]`, and typing it would no longer insert it.

                                                             *nvim-typst-edit*
Options ~

`edit.display_math`   The layout `ts$` gives the displayed math it makes:
                    `'lines'` (the default) puts each `$` on a line of its
                    own, as nvim-tex does with `\[ \]`; `'display'` writes
                    `$ x $` in place.
`edit.delim_list`     The answers `csd` accepts and the pair each one puts in
                    place: >lua
                      delim_list = {
                        ['('] = { '(', ')' },
                        ['['] = { '[', ']' },
                        ['{'] = { '{', '}' },
                        ['|'] = { '|', '|' },
                        ['||'] = { '‖', '‖' },
                        ['<'] = { '⟨', '⟩' },
                      }
<
`edit.delim_toggle_mod_list`
                    What `tsd`/`tsD` wrap the brackets in, in turn: the text
                    before and after them. Setting it replaces the list. >lua
                      delim_toggle_mod_list = {
                        { 'lr(', ')' },
                        { 'lr(', ', size: #150%)' },
                      }
<

15. CONCEAL                                               *nvim-typst-conceal*

With 'conceallevel' at 1 or more, nvim-typst shows symbols as the characters
they stand for: >typst
    $alpha in RR -> x^2 + bb(N)$ and #sym.arrow.r --- *bold* \#
<  shows as >
    $α ∈ ℝ → x² + ℕ$ and → — bold #
<
Conceal is on by default but, like any conceal, invisible until you set
'conceallevel' yourself, e.g. in `after/ftplugin/typst.lua`: >lua
    vim.opt_local.conceallevel = 2
<
What counts as math is read off the parse tree, so `alpha` in running text,
in a string, in a comment, in raw text or in code such as `$#f(alpha)$` is
left as it is. The replacements are ephemeral extmarks drawn by a decoration
provider, so nothing is stored in the buffer and they work under tree-sitter
highlighting as well as under `syntax/typst.vim`. Needs the `typst`
tree-sitter parser.

The symbols are every variant of Typst's `sym` module that is a single
visible character, including modifiers: `phi.alt` is ϕ, `arrow.r.long` is ⟶,
`eq.not` is ≠. A name with a modifier Typst does not know is left alone.

Options, under `conceal`:                        *nvim-typst-conceal-options*

  enabled          `true`     Conceal in Typst buffers at all.
  greek            `true`     `alpha`, `phi.alt`, `Omega` in math.
  math_symbols     `true`     The rest of `sym` in math -- `arrow.r`, `RR`,
                              `in`, `sum`, `infinity` -- and the math
                              shorthands `->`, `=>`, `<=`, `!=`, `:=`,
                              `...` and friends.
  math_fonts       `true`     `bb(R)` as ℝ, and `cal`, `scr`, `frak`,
                              `bold`, `sans`, `mono` of a single letter
                              or digit.
  math_super_sub   `true`     `x^2` as x², `x_1` as x₁, `x^(n+1)` as xⁿ⁺¹,
                              when every character has a Unicode super- or
                              subscript form.
  spacing          `true`     `thin`, `med`, `thick`, `quad`, `wide` in math
                              as a space.
  sym              `true`     `#sym.arrow.r` outside math.
  text_symbols     `true`     `--` as –, `---` as —, `...` as … outside math.
                              `~` and `-?` stay visible.
  styles           `true`     `*bold*`, `_emph_`, `#strong[..]`, `#emph[..]`
                              and `#underline[..]`: the markers are hidden,
                              the text is highlighted with
                              `NvimTypstBold`, `NvimTypstItalic` and
                              `NvimTypstUnderline` (linked to
                              `@markup.strong`, `@markup.italic`,
                              `@markup.underline`).
  escapes          `true`     `\#` as #, `\u{1F600}` as the character.
  item             `true`     The `-` of a bullet list item as •.
  custom           `{}`       Your own replacements, keyed by a math name or
                              the `name` of `#name` outside math: >lua
    conceal = { custom = { NN = 'ℕ', ['arrow.r.long'] = '⟶', todo = '☐' } }
<                             They take precedence over the built-in ones.

16. CITATIONS                                                *nvim-typst-cite*

|:TypstCite| (`<localleader>b`) searches DBLP (https://dblp.org) for a paper,
lets you pick one from a list and edit its key, appends the BibTeX entry to
the bibliography, and cites the key at the cursor. Every word of the query
has to occur in the title or in an author's name; the last word may be a
prefix. The prompts go through |vim.ui.input()| and |vim.ui.select()|, so a
picker plugin that replaces them takes over. Needs `curl`.

The bibliography is the first `.bib` file a `#bibliography(...)` names, in
the main file or in anything it includes, resolved as Typst resolves paths:
relative to the file, or to the project root when it starts with `/`. >typst
    #bibliography("refs.bib")
    #bibliography(("papers.yml", "/lit/refs.bib"), style: "ieee")
<
Hayagriva (`.yml`) files are read by Typst but not written to: if the
document names only those, |:TypstCite| refuses. Without any
`#bibliography(...)`, the first `.bib` file under the project root is used.
A loaded buffer of the bibliography is changed in place and written, unless
it has unsaved changes of its own; then it is left for you to save.

A paper that is already in the bibliography -- same key, DOI or DBLP record
-- is not added again, but cited under the key it has there.

Where the key goes:
  - `@key`, anywhere in markup, with a space in front if it would otherwise
    stick to the word before. A half-typed `@kn` in front of the cursor is
    replaced.
  - Inside `#cite(<kn|>)` the key completes the label; right behind
    `#cite(` it comes as `<key>`.
  - A key that `@` cannot take -- one with `/`, like DBLP's own
    `DBLP:conf/cgo/LeissaKH15` -- is written as `#cite(label("..."))`.
In insert mode the cursor ends up behind the key, still in insert mode.

`cite.dblp.enabled`       Search DBLP. Default `true`.
`cite.dblp.endpoint`      The SPARQL endpoint. DBLP's search API sits behind
                        a bot check that `curl` cannot pass, so the search
                        and the entry both go through SPARQL.
`cite.dblp.max_results`   Default `30`.
`cite.key`                The key a new entry gets: `'short'` for
                        `leissa2015graph` (first author, year, first
                        meaningful title word), `'source'` for DBLP's own,
                        or a function(entry) returning a string.
`cite.edit_key`           Ask for the key, prefilled, before adding the
                        entry. Default `true`.
`cite.curl`               The curl command, a string or a list.
`cite.timeout`            Seconds per request. Default `20`.

17. CONTEXT MENU                                     *nvim-typst-context-menu*

`<localleader>a` (|:TypstContextMenu|) acts on what is under the cursor:

  `@key`, `@key[...]`       Jump to `<key>` wherever it is attached in the
                          document; if there is no such label, to the
                          bibliography entry `key`.
  `#cite(<key>)`,           Jump to the bibliography entry, else the label.
  `#cite(label("key"))`
  `#ref(<key>)`             Jump to the label, else the bibliography entry.
  `<key>` (attached)        List its references (|vim.lsp.buf.references()|).
  `#include "x.typ"`,       Open the file.
  `#import "x.typ"`

  `#bibliography("x.bib")`  Open the bibliography.

Bibliography entries are found in `.bib` files and as top-level keys of

18. WORD COUNT                                              *nvim-typst-count*

|:TypstCountWords| and |:TypstCountLetters| count the text of the document.
There is no texcount for Typst, so the words are read off the parse tree:

  - Counted: the markup text -- body, headings, list and enumeration items,
    term lists, and the `[...]` content given to functions, such as
    `#strong[...]` or a figure's `caption: [...]`.
  - Not counted: math, code, strings, raw text, comments, labels,
    references (`@key`) and URLs, and the content of `#let`, `#set` and
    `#show`, which is only typeset where it is used.

A word is a run of non-blank characters with at least one letter or digit in
it, so `don't` and `well-known` are one word each, `--` or `.` none. Each CJK
character counts as a word. Letters are the letters and digits of the words.

The whole document is counted from the main file, with every `#include`
followed, depth first. Loaded buffers are counted as they stand, unsaved
changes included; other files are read from disk, and a missing one is
reported. With a [range] only those lines of the current buffer are counted,
including the files an `#include` in them pulls in.

The report of [!] lists, per file, the words (those in headings are counted
among them and also shown on their own), the letters, and the number of
inline and display formulas.

tinymist computes a word count of its own, part of its compile status
notifications; this one works without the LSP.

20. INSERT MODE MATH MAPPINGS                               *nvim-typst-imaps*

In math, a leader key -- a backtick by default -- followed by a short
sequence expands into a symbol or function, as nvim-tex's (and vimtex's)
imaps do: `` `a `` gives `alpha`, `` `jl `` gives `arrow.r`, `` `8 `` gives
`infinity`. The styles have a leader of their own, `@`, and wrap the next
character typed: `@bx` gives `bold(x)`, `@BR` gives `bb(R)`. nvim-tex uses
`#` for these; in Typst math `#` starts code.

Outside math the keys are inserted as they are typed, so the backtick still
starts raw text. Math that is being typed and has no closing `$` yet counts.
In math, `xalpha` is one name rather than `x` times `alpha`, so an expansion
that would run into a letter before or after the cursor gets a space in
between.

|:TypstImaps| (`<localleader>m`) lists the mappings. Options, under
`imaps`:

`imaps.enabled`   Default `true`.
`imaps.leader`    Typed before every entry without a leader of its own.
                Default `` ` ``.
`imaps.disabled`  `lhs` values of `imaps.list` to leave unmapped.
`imaps.list`      The mappings; see `lua/nvim-typst/config.lua` for the
                default list, nvim-tex's with the Typst names. Setting it
                replaces the default list. Each entry is a table:
                  `lhs`      typed after the leader
                  `rhs`      the text to insert, or a function(lhs)
                           returning it
                  `style`    instead of `rhs`: the function the next
                           typed character is passed to
                  `leader`   overrides `imaps.leader`
                  `wrapper`  when the entry expands: `'math'` (default)
                           or `'trivial'` (always), or a
                           function(lhs, expand) returning the text

More entries can be added at run time, to every Typst buffer: >lua

    require('nvim-typst.imaps').add({ lhs = 'o', rhs = 'compose' })
<

21. DIFFERENCES FROM NVIM-TEX                            *nvim-typst-nvim-tex*

The mappings, commands, options and events are nvim-tex's, with `Tex`
replaced by `Typst`. Where Typst differs:

  - One compiler, `typst`, with `watch` for continuous mode. There is no log
    file (`<localleader>q`) and nothing to clean but the PDF.
  - No SyncTeX. The `tinymist` viewer does forward search with
    `<localleader>v`; inverse search is a click in the preview, pushed by
    tinymist, so `<localleader>r` and `:TexReverseSearch` have no
    counterpart.
  - The main file directive is `// !TYPST main = ...`, and `b:typst_main`
    replaces `b:tex_main`.
  - `root_markers` is new: Typst's `--root` has no LaTeX counterpart.
  - The quickfix levels are `error` and `warning`; typst has no info level.
  - Typst has no environments, so the `e` text objects, `dse`/`cse` and
    `]r` are gone; `ac`/`ic`, `]m` and `dsc`/`csc` work on function calls
    instead, <F6> wraps lines in a content block and `tse` toggles lists
    between `-` and `+`.
  - `lr(…)` takes the place of `\left…\right` for `tsd`, `tsD` and <F8>;
    `edit.delim_toggle_mod_list` holds `lr(…)` wrappers, e.g. with a size.
  - Insert-mode `]]` is off by default (`mappings.insert_close`).
  - The style imaps use `@` rather than `#` as their leader, and the
    expansions are Typst names (`alpha`, `bold(x)`); see |nvim-typst-imaps|.
  - `K` opens a package's Typst Universe page rather than `texdoc`.
  - There is no TikZ; `<localleader>p` previews the math or code under the
    cursor instead (|:TypstPreviewFragment|, nvim-tex's `:TexTikzPreview`).
    typst renders it as a PNG for snacks.nvim, with no PDF to convert.
  - Citations are written as `@key`, into the `.bib` file a
    `#bibliography(...)` names.

 vim:tw=78:ts=8:ft=help:norl:
